# 用户文档规范

用户文档面向希望使用 Silex 构建应用的读者，重点是“完成任务所需的知识和步骤”，不要求读者先理解运行时内部实现。用户文档本轮只建立规范，具体学习内容后续按路径补充。

## 学习路径

用户文档按由浅入深的学习路径组织，而不是按内部 crate 平铺：

1. **开始使用**：安装环境、创建项目、运行开发服务器和构建发布版本。
2. **基础概念**：组件、视图、信号、事件、样式和资源。
3. **应用开发**：路由、表单、异步数据、状态持久化、国际化和错误边界。
4. **工程实践**：项目结构、测试、调试、性能分析和部署。
5. **参考资料**：常用 API、配置项、故障排查和术语表。

每一阶段都应链接到下一步；单篇文章解决一个明确任务，并在开头说明前置知识、预期结果和预计产物。

## 文章模板

用户教程建议包含以下部分：

- **目标**：读者完成后能做什么。
- **前置条件**：工具链、项目状态和必要依赖。
- **步骤**：按可执行顺序给出命令与代码。
- **验证**：说明如何看到成功结果，以及常见失败现象。
- **下一步**：链接到学习路径中的后续主题。

中文是主语言。首次出现的专有名词可以保留英文，并在中文语境中给出简短解释。命令、文件名、API 名称和错误消息保持原样；解释性文字不应只重复代码。

## 示例与安全

示例必须使用完整、最小且可复制的上下文。涉及密钥、令牌、个人数据或生产地址时使用占位符，并提醒读者通过环境变量或安全配置注入。教程不得要求读者执行无法说明影响范围的删除、覆盖或发布命令。

版本相关内容必须标注适用版本或验证日期。不要把开发中的 API 写成稳定承诺；如果行为依赖特性开关、目标平台或浏览器能力，必须在正文中说明。
